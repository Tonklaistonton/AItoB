# คู่มือติดตั้งและใช้งาน AItoB ฉบับกระชับ

ปรับปรุง 20 ตุลาคม 2026 ใช้ฟอนต์ Kanit ใน PDF

## เตรียมเครื่องและโค้ดต้นฉบับ

คู่มือนี้ใช้ติดตั้งบน Mac เครื่องใหม่หรือสภาพแวดล้อมแยก รันทีละช่วง และหยุดทันทีเมื่อพบ STOP หรือข้อผิดพลาด

| สิ่งที่ต้องมี | ข้อกำหนด |
| --- | --- |
| Mac และซอฟต์แวร์ | Apple Silicon, Python 3.12, Ollama และ Docker Desktop พร้อม Compose |
| เครื่องต้นแบบที่มีหลักฐาน | Apple M5 • RAM 24 GiB • macOS 27.0.1 ไม่ใช่สเปกขั้นต่ำที่รับรองทุกโหลด |
| เครือข่าย | ใช้อินเทอร์เน็ตเพื่อติดตั้งแพ็กเกจ ดาวน์โหลดโมเดล และเชื่อม Gmail เมื่อเลือกใช้ |

### 1 เตรียมคำสั่งใน Terminal บน Mac

เปิด Docker Desktop ให้พร้อม หาก SSH เข้า Mac แล้ว ให้รันคำสั่งต่อไปนี้ใน session ของ Mac

```bash
export PATH="$HOME/Applications/Ollama.app/Contents/Resources:$PATH"
export PATH="$HOME/.local/bin:/Applications/Ollama.app/Contents/Resources:$PATH"
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
python3 --version
docker compose version
ollama --version
```

### 2 เปิดโฟลเดอร์ source และตรวจไฟล์

แตก AItoB_Project_Source.zip ลงโฟลเดอร์ใหม่ แล้วเปิด Terminal ที่ AItoB_Source ซึ่งมี README_TH.md ก่อนรันคำสั่ง

```bash
python3 tools/verify_files.py
python3 -m unittest discover -s tests -v
```

ผลที่คาดหวัง: checksum ผ่านทุกไฟล์ และการทดสอบ 10 กรณีผ่าน การทดสอบนี้ใช้สิทธิ์จำลอง ไม่ได้ตรวจบริการจริง

### 3 คัดลอกและสร้าง config ใหม่

```bash
if [ -e "$HOME/aitob-lab" ]; then
  echo "STOP: existing lab found"
else
  cp -R project "$HOME/aitob-lab"
fi
```

หากพบ STOP ให้หยุด ไม่รันขั้นถัดไป หากคัดลอกสำเร็จแล้วจึงสร้าง config ด้วยคำสั่งนี้

```bash
python3 tools/prepare_local_config.py --lab "$HOME/aitob-lab"
```

ตัวช่วยสร้าง key ใหม่สำหรับ may และ ton พร้อม .env และ services/compose.json ไม่เขียนทับ config เดิมและไม่แสดง key

## ติดตั้งโมเดลและเปิดบริการ

คำสั่งหน้านี้รันบน Mac หลังเตรียม project และ config สำเร็จแล้ว ตั้ง LAB ใหม่ทุกครั้งที่เปิด Terminal อีกหน้าต่าง

### 4 เตรียมโมเดลและสร้าง images

หาก Ollama App เปิด server อยู่แล้วไม่ต้องรัน serve ซ้ำ หากยังไม่มี server ให้เปิด ollama serve ใน Terminal แยก แล้วรันชุดนี้ในอีกหน้าต่าง

```bash
export LAB="$HOME/aitob-lab"
ollama pull gemma4:12b
ollama list
ollama show gemma4:12b --verbose
docker build -t aitob-mcp-lab:day2 "$LAB/mcp-lab"
docker build -t aitob-gmail-lab:day2 "$LAB/gmail-lab"
```

ชุดส่งบันทึกแพ็กเกจจาก image เดิม และตรึง Open WebUI ด้วย image digest ตรวจผล build ก่อนดำเนินการต่อ ไม่เปลี่ยนเวอร์ชันเงียบ ๆ แล้วอ้างผลทดสอบเดิม

### 5 เปิด Gateway ใน Terminal แยก

```bash
cd "$HOME/aitob-lab/gateway"
python3 -u gateway.py
```

คงหน้าต่าง Gateway นี้ไว้ ระหว่างตรวจระบบให้ใช้ Terminal อีกหน้าต่างสำหรับคำสั่งส่วนที่เหลือ

### 6 เปิด Gmail และ Assistant แล้วเปิด WebUI

```bash
export LAB="$HOME/aitob-lab"
docker compose --env-file "$LAB/services/.env" \
  -f "$LAB/services/compose.json" config --quiet
docker compose --env-file "$LAB/services/.env" \
  -f "$LAB/services/compose.json" up -d
docker compose --env-file "$LAB/open-webui/.env" \
  -f "$LAB/open-webui/compose.yaml" up -d
```

### 7 ตรวจบริการก่อนตั้งหน้าจอ

```bash
curl --fail http://127.0.0.1:8000/health
curl --fail http://127.0.0.1:8002/health
```

คาดว่าได้ JSON ที่ status เป็น ok ทั้งสองบริการ แล้วเปิด http://127.0.0.1:3000 บน Mac พอร์ต host ยังคงผูกกับ 127.0.0.1 ไม่เปลี่ยนเป็น 0.0.0.0 เพื่อแก้ปัญหาการเชื่อมต่อ

## ตั้งบัญชีและใช้งานค่าใช้จ่าย

บัญชีผู้ใช้บน WebUI และสิทธิ์ตาม key เป็นคนละส่วน ต้องตั้ง key ให้ตรงคนและทดสอบแยกบัญชี

### 8 ติดตั้ง Pipe และกำหนดสิทธิ์

| ขั้นตอนใน Open WebUI | ค่าที่ใช้ |
| --- | --- |
| เข้าบัญชีผู้ดูแล → Admin Panel → Functions | สร้าง Function ด้วยโค้ด project/webui/aitob_openwebui_pipe.py |
| บันทึกและเปิดใช้งาน Function | ตรวจ version 0.1.3 และ BASE_URL = http://host.docker.internal:8002 |
| สร้างบัญชี Ton Finance และ May HR | ตั้ง AITOB_API_KEY ใน User Valves ของ AItoB Assistant แยกแต่ละบัญชี |
| เลือก key ของบุคคลนั้น | Ton ใช้ gateway/credentials/finance.key; May ใช้ gateway/credentials/hr.key |

ให้ผู้ดูแลเปิดไฟล์ key ในเครื่องแล้วตั้งค่าอย่างเป็นส่วนตัว ไม่พิมพ์ key ในแชต ไม่ตั้ง Finance key เป็นค่ากลาง และไม่ส่งไฟล์ credentials ลง Forms หรือ Git

### เข้าเว็บจาก Windows

เปิด Remote Login บน Mac และอนุญาตบัญชี SSH ให้ถูกต้อง จาก Command Prompt ฝั่ง Windows แทน mac-user และ mac-host ด้วยค่าของเครื่องที่ติดตั้ง

```cmd
ssh -N -L 3001:127.0.0.1:3000 mac-user@mac-host
```

เปิดหน้าต่าง SSH ค้างไว้ แล้วเข้า http://127.0.0.1:3001 บน Windows ถ้าปิด tunnel เว็บผ่านพอร์ตนี้จะเข้าไม่ได้

### ใช้งานไฟล์ CSV หรือ Excel

เข้า Ton Finance → New Chat → เลือก AItoB Assistant → แนบไฟล์หนึ่งไฟล์และรอให้อัปโหลดเสร็จ → ส่งคำสั่ง ตรวจไฟล์ค่าใช้จ่าย → ดาวน์โหลด CSV และเหตุผลรายแถวจากลิงก์ในคำตอบ

| ข้อมูลนำเข้า | ขอบเขตที่รองรับ |
| --- | --- |
| คอลัมน์ตามลำดับ | expense_id,vendor,amount |
| ไฟล์ | CSV UTF-8 หรือ .xlsx หนึ่งชีต ขนาดไม่เกิน 1,000,000 bytes ข้อมูลไม่เกิน 1,000 แถว |
| ยอดเงิน | THB เป็นบวก ไม่เกิน 1,000,000,000 บาท ทศนิยมไม่เกิน 2 ตำแหน่ง |
| ไม่รองรับ | สูตร merged cells macros และ external links |

คำสั่ง /download ส่งออกผล CSV คงที่ของระบบ ไม่ใช่ผลไฟล์แนบเก่า สำหรับไฟล์แนบให้ใช้ลิงก์ของคำตอบนั้น ไฟล์แนบไม่เขียนทับ CSV เดโมเดิม

## ตั้งค่า Gmail เมื่อเลือกใช้อีเมล

ส่วนอีเมลต้องตั้งค่าเพิ่มเติม ใช้บัญชีที่เจ้าของอนุญาต ชุดส่งไม่มี OAuth token หรือข้อมูลอีเมลจริง

### 1 กำหนดเจ้าของ mailbox

แก้ EXPECTED_EMAIL ใน gmail-lab/email_access.py เป็นอีเมลที่อนุญาต แทน mailbox-owner-1@example.com ค่าต้นแบบ OWNER_USER และ MAILBOX_OWNER คือ ton จึงใช้ key ของ Ton กับเส้นทางอีเมลนี้

### 2 เตรียม Google OAuth

สร้าง Google Cloud project → เปิด Gmail API → ตั้ง OAuth consent → สร้าง OAuth client แบบ Desktop app → บันทึกไฟล์เป็น gmail-lab/credentials/client_secret.json บน Mac เท่านั้น

### 3 เปิด callback แล้วให้เจ้าของยืนยันบัญชี

ถ้าใช้ browser บน Windows ให้เปิด tunnel ตามหัวข้อด้านล่างก่อนรันคำสั่ง authorize

```bash
export LAB="$HOME/aitob-lab"
docker run --rm -it -p 127.0.0.1:8765:8765 \
  -v "$LAB/gmail-lab:/app" -w /app \
  aitob-gmail-lab:day2 python authorize_gmail.py
```

เปิดลิงก์ที่โปรแกรมแสดงใน browser บน Mac แล้วให้เจ้าของบัญชีทำขั้นตอนยืนยันด้วยตนเอง ตัวช่วยบันทึก token.json ในเครื่อง ถ้ามี token อยู่แล้วโปรแกรมจะหยุด ไม่สั่งลบ token เพื่อฝืนรันซ้ำ

### หากยืนยันบัญชีด้วย browser ฝั่ง Windows

เปิด tunnel พอร์ต 8765 ใน Command Prompt อีกหน้าต่างก่อนเริ่ม authorize แล้วคงหน้าต่างไว้จนยืนยันเสร็จ

```cmd
ssh -N -L 8765:127.0.0.1:8765 mac-user@mac-host
```

อย่าส่ง URL ที่มี state หรือ code, token.json, client_secret.json หรือ key ให้ผู้อื่น

### 4 สร้างขอบเขตอีเมลและทดลองใช้

สร้าง Gmail label ชื่อ AItoB-Demo และใส่เฉพาะอีเมลตัวอย่างที่อนุญาต จากบัญชี Ton ส่งคำสั่ง เช่น ค้นหาอีเมลใน AItoB-Demo เรื่องประชุม 1 ฉบับ อ่านแล้วสรุป

| จุดตรวจ | ความหมาย |
| --- | --- |
| gmail.readonly | OAuth อนุญาตอ่าน Gmail ของบัญชี ส่วนโค้ดกรองเจ้าของและ label เพิ่ม ไม่ใช่ OAuth ที่จำกัดเฉพาะ label |
| ค้นก่อนอ่าน | Agent ใช้รหัสจากผลค้นในคำขอเดียวกัน จำกัดการเรียกเครื่องมือ 4 ครั้งและอ่าน 2 ฉบับต่อคำขอ |
| truncated เป็น true | สรุปจากข้อความบางส่วน ต้องไม่อ้างว่าอ่านครบ |

## ตรวจรับระบบและแก้ปัญหา

ตรวจเครื่องที่ติดตั้งใหม่ด้วยข้อมูลสังเคราะห์ บันทึกผลใหม่ ไม่ใช้ผลของเครื่องเดิมแทนผลตรวจรับ

### เกณฑ์ตรวจรับ

| กรณี | ผลที่ต้องได้ |
| --- | --- |
| Ton ส่ง fixtures/AItoB_ค่าใช้จ่ายสังเคราะห์.xlsx | 6 แถว → ผ่าน 3 ซ้ำ 1 ปฏิเสธ 2 ยอด 2,000.00 บาท |
| ดาวน์โหลดผลจากคำตอบ | CSV ตรง fixtures/expected_cleaned.csv และ audit ตรง fixtures/expected_audit.csv พร้อมตรวจรหัสไฟล์นำเข้า |
| May สั่งตรวจค่าใช้จ่าย / เปิด URL ไฟล์ Ton | ถูกปฏิเสธ และไม่ได้เนื้อหาไฟล์ของ Ton |
| ไม่ส่ง key / key ผิด / ส่ง role เพิ่มใน request | 401 เมื่อ key ไม่ถูกต้อง และข้อมูล client ไม่ยกระดับสิทธิ์ |
| May ถามนโยบายวันลาตัวอย่าง | ตอบ 12 วันต่อปี แจ้งล่วงหน้า 3 วัน พร้อม source hr-leave |
| Gmail เมื่อเปิดใช้ | เจ้าของตรง อ่านในขอบเขตแอป และปฏิเสธผู้ใช้คนอื่น |

### อาการและจุดตรวจ

| อาการ | ตรวจตามลำดับ |
| --- | --- |
| Windows เข้า localhost:3001 ไม่ได้ | SSH tunnel ยังเปิดอยู่ และเว็บบน Mac พอร์ต 3000 ทำงาน |
| SSH Connection refused / timeout | host, พอร์ต, Remote Login, บัญชีที่อนุญาต และเครือข่ายหรือ VPN |
| docker หรือ ollama command not found | PATH ใน session SSH และตำแหน่งที่ติดตั้งจริง |
| ติดต่อ Docker daemon ไม่ได้ | เปิด Docker Desktop และรอให้พร้อม |
| 401 / 403 | User Valves และสิทธิ์ใน keys.json ไม่ใช้ prompt เปลี่ยน role |
| 502 หรือ timeout | Gateway, Ollama, Gmail และการเชื่อมผ่าน host.docker.internal |
| Gmail mailbox mismatch | EXPECTED_EMAIL ไม่ตรง OAuth profile ให้เจ้าของตรวจบัญชี |
| ไฟล์ 413 / 422 | ขนาด schema จำนวนแถว จำนวนชีต สูตร และรูปแบบยอดเงิน |
| แนบไฟล์แล้วไม่ตรวจ / ตัวติดตั้งขึ้น STOP | ตรวจ Pipe 0.1.3 และคำสั่งตรวจไฟล์ ไม่ปิด source guard เพื่อฝืนติดตั้ง |

บันทึกเฉพาะขั้นตอน รุ่น และรหัสสถานะ ไม่ส่ง log ที่มี key, headers, อีเมลจริง หรือข้อมูลการเงินจริง

## ดูแลระบบและข้อจำกัด

ตรวจบริการก่อนใช้งานทุกวัน แยกการสำรองข้อมูลลับออกจาก ZIP source ที่ใช้ส่งงาน

### ก่อนเริ่มงาน

- ตรวจว่า Mac ตื่น เครือข่ายพร้อม Ollama และ Docker Desktop เปิด และ Gateway ยังทำงาน

- หากใช้ Gateway ใน Terminal ต้องเปิดหน้าต่างนั้นไว้ หากใช้ Windows ต้องเปิด SSH tunnel ด้วย

- เมื่อกลับเข้า Terminal ใหม่ ตั้ง export LAB="$HOME/aitob-lab" ก่อนใช้คำสั่งที่อ้าง $LAB

### ตรวจสถานะบริการบน Mac

```bash
export LAB="$HOME/aitob-lab"
docker compose --env-file "$LAB/services/.env" \
  -f "$LAB/services/compose.json" ps
docker compose --env-file "$LAB/open-webui/.env" \
  -f "$LAB/open-webui/compose.yaml" ps
```

### การสำรองและอัปเดต

- สำรอง key, OAuth, Open WebUI data และไฟล์ที่ต้องรักษาในพื้นที่จำกัดสิทธิ์ ไม่ส่งข้อมูลเหล่านี้รวมกับ source

- ใช้วิธีสำรองฐานข้อมูลที่สอดคล้องกับ SQLite และ WAL ไม่คัดลอกไฟล์ฐานข้อมูลที่กำลังเขียนอย่างไม่ครบชุด

- เก็บรุ่นเดิม ทดสอบอัปเดตและการกู้คืนในระบบแยกก่อนใช้จริง ไฟล์ LaunchAgent ใน reference มี path ของเครื่องเดิม ต้องปรับและทดสอบก่อนใช้

### ขอบเขตที่ยังต้องทดสอบ

| ตรวจแล้วในชุดส่ง | ยังไม่ยืนยันครบ |
| --- | --- |
| source, checksum, การสร้าง config และการปฏิเสธเขียนทับ config เดิม; ชุดทดสอบค่าใช้จ่าย 10 กรณี | ติดตั้งใหม่ครบวงจรบน Mac ว่าง จำนวนผู้ใช้พร้อมกัน และการซ้อมกู้คืน |
| key ตรวจสิทธิ์ที่ backend และไฟล์มีเจ้าของใน WebUI | ชื่อบัญชี WebUI ยังไม่ผูกกับตัวตน gateway แบบครบวงจร |
