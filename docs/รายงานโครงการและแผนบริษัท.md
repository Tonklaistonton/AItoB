# รายงานโครงการและแผนบริษัท AItoB ฉบับกระชับ

ปรับปรุง 20 ตุลาคม 2026 ใช้ฟอนต์ Kanit ใน PDF

## AItoB ภาพรวมโครงการ

บริการสำรวจ ออกแบบ ติดตั้ง และดูแล AI ภายในองค์กร เพื่อช่วยงานซ้ำและทำให้ผลลัพธ์ตรวจสอบได้

### ลูกค้าและปัญหาที่ต้องการแก้

กลุ่มเป้าหมายคือองค์กรขนาดเล็ก กลาง และใหญ่ โดยเริ่มจากหนึ่งทีมและหนึ่งงานที่วัดผลได้ ก่อนขยายตามปริมาณงานและจำนวนผู้ใช้

| งานของลูกค้า | ปัญหา | แนวทางของ AItoB |
| --- | --- | --- |
| สรุปค่าใช้จ่ายรายวัน | ทำซ้ำและเสี่ยงรวมยอดผิด | ตรวจข้อมูล รวมยอด และแสดงรายการที่ไม่ผ่าน |
| อ่านอีเมล | ใช้เวลาค้นและจับประเด็น | ค้นและสรุปอีเมลที่มีสิทธิ์ พร้อมแหล่งอ้างอิง |
| ทำความสะอาดข้อมูล | ใช้หลายสูตรและหลายขั้นตอน | ตรวจรายการซ้ำและข้อมูลผิด แล้วส่งออก CSV |
| ค้นเอกสารองค์กร | ข้อมูลกระจายและมีสิทธิ์ต่างกัน | ค้นข้อมูลตามสิทธิ์และตอบพร้อมรหัสเอกสาร |

### สิ่งที่พัฒนาในต้นแบบ

- หน้าสนทนา Open WebUI เชื่อม Ollama และเครื่องมือเฉพาะงานผ่าน AItoB Assistant

- รับ CSV และ Excel สรุปจำนวนแถวและยอดเงิน พร้อมดาวน์โหลดไฟล์สะอาดและรายงานรายแถว

- ตรวจสิทธิ์ที่ระบบหลังบ้าน และจำกัดเครื่องมือที่แต่ละ key เรียกใช้ได้

### คุณค่าที่ต้องพิสูจน์กับลูกค้า

ลดเวลาทำงานรวม ลดข้อผิดพลาด และควบคุมต้นทุน โดยวัดรวมเวลาที่คนตรวจและแก้ผลลัพธ์ ปัจจุบันยังไม่มีผลวัดการลดเวลาหรือ ROI ของลูกค้า

สถานะข้อมูล: pain point มาจากเจ้าของโครงการ ยังไม่ใช่ผลสำรวจลูกค้าที่ระบุจำนวนตัวอย่าง

## ระบบและเครื่องที่ใช้จริง

Ollama คือระบบรันโมเดล ส่วน gemma4:12b คือโมเดลที่เลือกใช้ ทั้งสองเป็นคนละองค์ประกอบกัน

### เส้นทางทำงานหลัก

| ประเภทงาน | ลำดับการทำงาน |
| --- | --- |
| ไฟล์ค่าใช้จ่ายที่แนบ | WebUI → ตรวจสิทธิ์ → อ่านไฟล์ของเจ้าของ → ตรวจข้อมูลและรวมยอด → ส่งออก CSV และ audit |
| คำถามเอกสารและอีเมล | Agent ใช้ Gateway และ Ollama เลือกเครื่องมือ → ตรวจคำสั่ง → เรียก MCP tools → ตอบพร้อมแหล่งข้อมูล |

ยอดเงินใช้โปรแกรมและ Decimal คำนวณ ส่วนไฟล์แนบในเส้นทาง AItoB ไม่ส่งเนื้อหาให้ LLM ระบบอัปโหลดทั่วไปของ WebUI เป็นอีกชั้นหนึ่ง

### เครื่องและซอฟต์แวร์ต้นแบบ

| รายการ | ค่าที่ตรวจพบ |
| --- | --- |
| เครื่องและ RAM | Apple M5 แบบ arm64 • RAM 24 GiB |
| ระบบปฏิบัติการ | macOS 27.0.1 |
| Ollama และโมเดล | Ollama 0.40.5 • gemma4:12b ขนาดไฟล์ที่แสดง 7.7 GB |
| รายละเอียดโมเดล | ประมาณ 12.4B parameters • MLX • nvfp4 |
| หน้าจอและ Pipe | Open WebUI 0.12.3 • Pipe 0.1.3 |
| ส่วนบริการ | Docker 29.7.2 • Python ใน image 3.12.15 • MCP 2.3.0 |

### ข้อพิจารณาก่อนเลือกเครื่องให้ลูกค้า

- 24 GiB เป็น RAM ของเครื่องที่ทดสอบ ไม่ใช่สเปกขั้นต่ำที่รับรองสำหรับทุกองค์กร

- RAM ต้องรองรับโมเดล หน่วยความจำสำหรับบริบท (KV cache) ระบบปฏิบัติการ Docker และงานที่ทำพร้อมกัน ขนาดไฟล์โมเดลไม่เท่ากับ RAM ที่ต้องใช้ทั้งหมด

- โมเดลรายงานความยาวบริบทสูงสุด 262,144 tokens แต่โค้ดหลายเส้นทางใช้ 4,096 tokens ต้องทดสอบก่อนเพิ่มบริบทหรือจำนวนผู้ใช้

ใช้โมเดลที่ฝึกมาแล้วร่วมกับคำสั่งและเครื่องมือ ยังไม่มีการฝึกปรับแต่งโมเดล หรือผลเปรียบเทียบหลายโมเดลแบบควบคุม

## ผลทดสอบและขอบเขตระบบ

ผลบน Mac และ WebUI ทดสอบเมื่อ 19 ตุลาคม 2026 ส่วน source และเวอร์ชันระบบเก็บเมื่อ 20 ตุลาคม 2026

### ผลตรวจไฟล์ Excel สังเคราะห์

ก่อนตรวจ 6 แถว / ผ่าน 3 แถว / ซ้ำ 1 แถว / ปฏิเสธ 2 แถว

ยอดรวมที่ผ่านตรวจ 2,000.00 บาท ดาวน์โหลด cleaned CSV และ audit CSV ได้จริง และตรวจข้อมูลกับรหัสตรวจไฟล์แล้ว

### การตรวจสิทธิ์และความถูกต้อง

| กรณีทดสอบ | ผลและขอบเขต |
| --- | --- |
| Ton Finance ส่ง Excel | ได้ผล 6 → 3 / 1 / 2 และยอด 2,000.00 บาท |
| May HR สั่งตรวจค่าใช้จ่าย | ถูกปฏิเสธผ่านหน้าเว็บ รอบนี้ไม่มีไฟล์แนบ |
| HR เปิด URL ไฟล์ของ Ton | ไม่ได้รับเนื้อหาทั้ง CSV และ audit ของ Ton |
| Backend รับ key | ไม่ส่ง key หรือส่งผิด: 401 • HR: 403 • Finance: 200 ตามกรณีทดสอบ |
| ชุดทดสอบใน ZIP | ผ่าน 10 กรณีแบบแยกส่วน ใช้การยืนยันสิทธิ์จำลอง |

### ไฟล์ค่าใช้จ่ายที่รองรับ

CSV UTF-8 หรือ .xlsx หนึ่งชีต คอลัมน์ expense_id, vendor, amount ขนาดไม่เกิน 1,000,000 bytes และข้อมูลไม่เกิน 1,000 แถว ไม่รองรับสูตร merged cells macros และ external links

### ข้อจำกัดที่ต้องทราบ

- บัญชี WebUI ยังไม่ผูกกับตัวตนระบบหลังบ้านแบบครบวงจร ผู้ถือ key ได้สิทธิ์ตาม key

- ค้นเอกสารด้วยคำสำคัญและเอกสารตัวอย่าง ยังไม่มีฐานข้อมูลเวกเตอร์หรือระบบนำเข้าคลังเอกสารเต็มรูปแบบ

- Gmail ยังใช้บริการภายนอก ส่วนการทดสอบติดตั้งเครื่องใหม่ การรองรับผู้ใช้พร้อมกัน และการกู้คืนยังไม่ครบ

หลักฐานนี้ยืนยันเฉพาะกรณีที่ทดสอบ ไม่ใช่การรับรองความปลอดภัยหรือความพร้อมใช้งานทั้งระบบ

## เป้าหมายปีแรกและการแบ่งกำไร

เป้าหมายธุรกิจต้องแยกจากผลดำเนินงานจริง เงินลงทุนจาก Investor ไม่บวกเป็นรายได้หรือกำไรจากการให้บริการ

| ประมาณการปีแรก | จำนวน |
| --- | --- |
| รายได้เป้าหมาย | 5,100,000 บาท |
| งบต้นทุน 400,000 บาท × 12 เดือน | 4,800,000 บาท |
| ผลต่างรายได้หักงบต้นทุน | 300,000 บาท |
| เป้าหมายคืนทุน / มูลค่าบริษัท | ประมาณ 1 ปี / 20,400,000 บาท |

ตัวอย่างรายได้ 5.1 ล้านบาท: Setup 10 บริษัท = 3 ล้านบาท และค่าดูแลรวม 60 เดือนลูกค้า = 2.1 ล้านบาท ตัวอย่างนี้ยังไม่ใช่ยอดขายที่มีสัญญา

เป้าคืนทุนและมูลค่าบริษัทยังไม่มีเงินลงทุนเริ่มต้น ตารางกระแสเงินสด และวิธีประเมินมูลค่ารองรับ ส่วนผลต่าง 300,000 บาทยังต้องปรับภาษีและรายการที่ไม่ระบุก่อนใช้จัดสรรจริง

## แผนดำเนินงานและการวัดผล

เริ่มจากงานที่มีข้อมูลพร้อมและตรวจคำตอบได้ แล้วขยายเมื่อผ่านเกณฑ์ที่ตกลงกับลูกค้า

| ระยะ | งานหลัก | ผลส่งมอบ |
| --- | --- | --- |
| 1 สำรวจ | สัมภาษณ์และสังเกตงาน เก็บปริมาณ เวลา และข้อผิดพลาด | ปัญหางานเดิม ค่าตั้งต้น และขอบเขตข้อมูล |
| 2 ออกแบบ | เลือกเครื่อง โมเดล การเชื่อมระบบและสิทธิ์ | แบบระบบ งบประมาณ และเกณฑ์ตรวจรับ |
| 3 สร้างต้นแบบ | ทดสอบข้อมูลสังเคราะห์และกรณีไม่มีสิทธิ์ | ระบบต้นแบบกับผลที่ทำซ้ำได้ |
| 4 นำร่อง | ทีมจำกัดใช้งาน โดยคนตรวจผลสำคัญ | เวลารวม คุณภาพ และปัญหาเทียบงานเดิม |
| 5 ส่งมอบ | ตรวจรับ อบรม และทดสอบการกู้คืน | source คู่มือ และผู้ดูแลที่รับผิดชอบ |
| 6 ดูแลและขยาย | ติดตามบริการ ทบทวนสิทธิ์ ทดสอบก่อนอัปเดต | ขยายเมื่อผ่านการทดสอบโหลดและงบที่ตกลง |

### เกณฑ์วัดผลที่ใช้กับลูกค้า

- เวลา: รวมเวลาคนอ่าน ตรวจ แก้ และนำผลไปใช้ ไม่ใช้เวลา inference เพียงอย่างเดียว

- คุณภาพ: ยอดตรง รายการไม่ตกหล่น สรุปไม่แต่งข้อมูล และมีแหล่งอ้างอิง

- สิทธิ์: ปฏิเสธ key ผิด เครื่องมือที่ไม่อนุญาต และไฟล์ข้ามผู้ใช้

- ต้นทุน: รวมเครื่อง ค่าไฟ การติดตั้ง ดูแล สำรองข้อมูล อบรม และเวลาคนตรวจ

### งานก่อนขยายใช้งานจริง

ผูกบัญชีกับสิทธิ์ระบบหลังบ้าน จัดการอายุและการเพิกถอน key ทดสอบผู้ใช้พร้อมกัน กำหนดอายุเก็บข้อมูล และซ้อมกู้คืนในสภาพแวดล้อมแยก โดยเจ้าของงานตรวจผลสำคัญ
